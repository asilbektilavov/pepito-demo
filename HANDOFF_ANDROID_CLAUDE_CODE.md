# Передача Android-проекта AI-агенту Claude Code

> Гайд для бэкенд-разработчика, который хочет отдать Android-приложение
> (`client-app`, Kotlin) на разработку и поддержку агенту **Claude Code**,
> не имея опыта в Android.

Цель этого документа — чтобы человек, никогда не писавший под Android, смог
**руководить** агентом: ставить задачи, проверять результат и мержить, а не
разбираться в тонкостях Gradle и Jetpack. Весь код пишет агент.

---

## 0. Как это вообще работает (2 минуты чтения)

Claude Code — это агент, который:
- **читает** твой репозиторий целиком,
- **пишет и правит** код,
- **сам собирает проект и гоняет тесты** в терминале,
- **делает коммиты и создаёт merge/pull request'ы**.

Твоя работа как «заказчика» сводится к трём вещам:
1. Один раз хорошо **подготовить репозиторий** (об этом ниже — это самое важное).
2. **Ставить задачи** человеческим языком.
3. **Проверять** результат: собралось ли, прошли ли тесты, работает ли на устройстве.

Главное правило: **чем лучше агент может сам себя проверить (собрать проект,
запустить тесты, линтер), тем меньше он галлюцинирует и тем меньше нужно
понимать в Android тебе.** 80% успеха — это рабочая команда сборки.

## 1. Где запускать агента

Есть два варианта, выбери один:

### Вариант А. Claude Code на компьютере (рекомендую для старта)
- Установить на Mac/Linux/Windows(WSL): `npm install -g @anthropic-ai/claude-code`,
  затем в папке проекта команда `claude`.
- Плюс: агент реально собирает APK локально, ты можешь тут же поставить его на телефон.
- Минус: нужно один раз настроить Android-окружение на машине (см. раздел 3).

### Вариант Б. Claude Code на вебе / в облаке (claude.ai/code)
- Подключаешь Git-репозиторий, агент работает в облачном контейнере.
- Плюс: ничего не ставить локально, удобно давать задачи с телефона.
- Минус: в облаке **обязательно** должен быть настроен автоматический установщик
  Android SDK (иначе агент не сможет собрать проект — см. раздел 3.3 про SessionStart-хук).

> Для GitLab (`git.fivetaxi.uz`): проще всего клонировать репозиторий локально и
> запускать Claude Code там (Вариант А). Облачная интеграция Claude Code
> заточена в первую очередь под GitHub.

## 2. Подготовка репозитория — самый важный раздел

Прежде чем давать первую задачу, положи в **корень репозитория** файл
`CLAUDE.md`. Агент читает его автоматически в начале каждой сессии. Это
«постоянная память» и правила проекта. Шаблон — в конце документа (раздел 8),
скопируй и заполни.

Что в нём должно быть:
- как собрать проект **одной командой**;
- как запустить тесты и линтер;
- структура модулей (где экраны, где сеть, где модели);
- архитектура и стек (MVVM? Compose или XML? Hilt? Retrofit?);
- код-стайл и договорённости;
- чего **нельзя** делать (не трогать `signingConfig`, не коммитить ключи и т.п.).

Не нужно писать роман. Нужно, чтобы бэкендер, прочитав `CLAUDE.md`, понял проект
за 5 минут — тогда и агент поймёт.

## 3. Android-окружение (чтобы агент мог собирать проект)

Это то, чего в бэкенде нет и что удивляет. Для сборки Android-проекта нужны:

### 3.1 JDK (Java)
Обычно **JDK 17** для современных проектов. Проверить: `java -version`.

### 3.2 Android SDK
Набор инструментов Google. Ставится либо через Android Studio, либо через
командную строку (`cmdline-tools`). После установки должна существовать
переменная окружения `ANDROID_HOME` (или файл `local.properties` с `sdk.dir=...`).

Минимально нужны компоненты (версии агент возьмёт из `build.gradle`):
- `platform-tools`
- `platforms;android-XX` (XX = compileSdk из проекта)
- `build-tools;XX.X.X`

### 3.3 Gradle
Система сборки Android. **Ничего ставить не надо** — в проекте есть `./gradlew`
(Gradle Wrapper), он скачает нужную версию сам. Ключевые команды:

```bash
./gradlew assembleDebug        # собрать debug-APK
./gradlew testDebugUnitTest    # unit-тесты
./gradlew lint                 # статический анализатор Android
./gradlew ktlintCheck          # проверка код-стайла (если подключён ktlint)
```

### 3.4 Проверка «золотой» команды
Прежде чем звать агента — убедись сам, что проект собирается **чистой** командой:

```bash
./gradlew assembleDebug
```

Если она проходит у тебя в терминале — пройдёт и у агента. Если падает —
**сначала почини сборку** (можно попросить об этом самого агента первой задачей:
«проект не собирается, вот лог ошибки, разберись»), и только потом давай фичи.

> **Для облачного Claude Code:** добавь SessionStart-хук, который на старте
> сессии ставит JDK + Android SDK и прогревает Gradle. Иначе облачный агент
> стартует в пустом контейнере без Android SDK. Попроси об этом Claude Code
> прямо: *«настрой SessionStart hook, который устанавливает Android SDK и
> собирает проект»* — у него есть готовый навык для этого.

## 4. Как ставить задачи агенту

Пиши как обычному разработчику — человеческим языком, но конкретно.

**Плохо:** «сделай экран профиля красивее».

**Хорошо:**
> На экране профиля (`ProfileScreen`) добавь кнопку «Выйти». По нажатию —
> очистить токен через `AuthRepository.logout()` и перейти на экран логина.
> Кнопку размести внизу экрана, стиль как у остальных кнопок в проекте.

Полезные приёмы:
- **Ссылайся на существующие вещи**: «сделай как на экране заказа», «используй
  тот же паттерн, что в `OrderViewModel`». Агент подхватит стиль проекта.
- **Проси показать план до кода** для крупных задач: «сначала опиши план, потом
  реализуй». В Claude Code для этого есть режим планирования.
- **Всегда добавляй критерий готовности**: «убедись, что `./gradlew assembleDebug`
  и unit-тесты проходят». Тогда агент сам себя проверит перед тем, как сказать «готово».
- **Одна задача = один запрос.** Не сваливай 10 фич в один промпт.

## 5. Как проверять результат (без знания Android)

Ты не читаешь Kotlin — и не надо. Проверяй по «внешним» признакам:

1. **Собралось ли:** попроси агента приложить вывод `./gradlew assembleDebug`.
   Слово `BUILD SUCCESSFUL` — хорошо, `BUILD FAILED` — вернуть на доработку.
2. **Прошли ли тесты:** `./gradlew testDebugUnitTest` → `BUILD SUCCESSFUL`.
3. **Посмотреть глазами на устройстве.** Debug-APK лежит в
   `app/build/outputs/apk/debug/app-debug.apk`. Установить на телефон:
   ```bash
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   ```
   (телефон в режиме разработчика + USB-отладка). Либо собрать через Android Studio.
4. **Прочитать summary агента.** Claude Code в конце пишет, что именно поменял —
   этого достаточно для ревью на уровне «то ли он сделал, что я просил».

Если что-то не так — просто напиши «не работает вот это, вот что вижу», агент
доисправит. Не нужно самому лезть в код.

## 6. Рабочий процесс с Git (GitLab)

Договорись с агентом о простом workflow — впиши это в `CLAUDE.md`:
- каждую задачу агент делает в **отдельной ветке** (`feature/...`, `fix/...`);
- в конце — коммит с понятным сообщением и **merge request** в GitLab;
- **не пушить напрямую в `main`/`master`/`dev`**.

Ветку ты потом мержишь сам после проверки. Это твоя «кнопка контроля».

> Claude Code «из коробки» хорошо дружит с GitHub (создание PR, чтение CI).
> С GitLab он тоже работает как с обычным git (клон, ветки, коммиты, пуш),
> но автоматического создания merge request'ов и чтения CI-логов через API
> может не быть — тогда MR создаёшь ты в вебе GitLab по запушенной ветке.

## 7. Частые грабли именно для Android + AI-агента

- **Секреты и ключи.** В Android есть `keystore` для подписи релиза, а также
  API-ключи (карты, пуши). Их **нельзя** коммитить. Явно запрети это в `CLAUDE.md`
  и держи их в `local.properties` / переменных окружения / CI-секретах.
- **Версии SDK.** Не давай агенту «на всякий случай» поднимать `compileSdk`,
  `minSdk`, версии Gradle или Kotlin — это ломает сборку. Обновление версий —
  отдельная осознанная задача, а не побочный эффект.
- **Долгая первая сборка.** Первый `./gradlew` качает зависимости — это нормально,
  несколько минут. Не считай это зависанием.
- **UI-тесты (инструментальные) требуют эмулятора/устройства.** В облаке их обычно
  не гоняют. Полагайся на unit-тесты + ручную проверку APK.
- **Не проси «отрефакторить весь проект» одним запросом.** Дели на маленькие шаги.

## 8. Шаблон `CLAUDE.md` (скопируй в корень репозитория и заполни)

```markdown
# CLAUDE.md — правила проекта client-app

## О проекте
Android-клиент такси FiveTaxi. Язык: Kotlin.
UI: <Jetpack Compose | XML-верстка>.
Архитектура: <MVVM | MVI | Clean Architecture>.

## Стек и библиотеки
- DI: <Hilt | Koin | нет>
- Сеть: <Retrofit + OkHttp | Ktor>
- Асинхронность: Kotlin Coroutines + Flow
- Навигация: <Navigation Compose | Jetpack Navigation | своя>
- Локальное хранилище: <Room | DataStore | SharedPreferences>

## Как собрать и проверить (ОБЯЗАТЕЛЬНО запускать перед "готово")
```bash
./gradlew assembleDebug        # сборка
./gradlew testDebugUnitTest    # unit-тесты
./gradlew lint                 # анализатор
./gradlew ktlintCheck          # код-стайл (если есть)
```
Готовый APK: app/build/outputs/apk/debug/app-debug.apk

## Требования к окружению
- JDK 17
- Android SDK, compileSdk = <XX>, minSdk = <XX>

## Структура модулей
- app/ — точка входа, экраны
- data/ — репозитории, сеть, модели API
- domain/ — бизнес-логика, use-case'ы
- (опиши реальную структуру своего проекта)

## Договорённости
- Каждую задачу — в отдельной ветке feature/* или fix/*.
- Не пушить в main/master/dev напрямую, только через merge request.
- Следовать существующему стилю кода и именованию.
- Комментарии и текст в коде — на английском (или как принято у вас).

## ЧЕГО НЕЛЬЗЯ ДЕЛАТЬ
- Не коммитить keystore, API-ключи, пароли, .env, local.properties.
- Не менять compileSdk/minSdk/versionCode/versionName без отдельной задачи.
- Не менять signingConfig и конфигурацию релизной подписи.
- Не удалять существующие тесты, чтобы "сборка прошла".
```

6. [ ] Дальше — ставить фичи по одной, проверять `BUILD SUCCESSFUL` и APK на телефоне.
7. [ ] Мержить ветки самому после проверки.

Если сборка проекта зелёная и `CLAUDE.md` заполнен — дальше бэкендер спокойно
руководит разработкой, не написав ни строчки Kotlin.
